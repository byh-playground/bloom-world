# BLOOM PLAYGROUND

게임 전시 페이지: [BLOOM PLAYGROUND](https://byh-playground.github.io/bloom-world/playground/)

이 폴더의 **`index.html`만** 전시 사이트의 원본입니다. 게임 저장소가 제공해야 하는 `bloom-game.json`의 규격은 [MANIFEST.md](MANIFEST.md)와 [스키마](bloom-game.schema.json)가 원본입니다. 게임 파일이나 배포용 번들은 여기에 복사하지 않습니다.

## 릴리즈 표시

- 각 게임의 공개 GitHub 저장소에서 고유 Git 태그를 조회합니다. `vMAJOR.MINOR.PATCH`는 Stable, `nightly-YYYYMMDDTHHMMSSZ-SHA12`는 Nightly입니다.
- `전체 게임`과 채널을 지정하지 않은 상세 URL은 Stable 우선, 없으면 Nightly입니다. 목록의 채널·장르·검색 조건은 상세의 기본 채널 선택에 영향을 주지 않습니다. 채널 탭은 해당 태그를 가진 게임만 표시합니다.
- `#/game/<게임 ID>/stable` 또는 `/nightly`처럼 채널을 지정한 상세 URL은 그 채널을 유지합니다. 해당 태그가 없으면 미등록으로 표시하며 다른 채널의 실행 주소로 자동 대체하지 않습니다. 등록된 다른 채널은 상세 버튼으로 선택할 수 있습니다.
- Nightly는 현재 개발 스냅샷으로서 **정상 작동을 보장하지 않습니다.** Stable은 명시적 검증 및 승인 태그만 표시합니다. 태그가 없거나 조회가 실패하면 Stable이라고 추정하지 않습니다.
- 태그 시점의 원본 `index.html`은 현재 GitHack 정적 CDN(`rawcdn.githack.com`)에서 프리뷰합니다. 이는 타사 무료 서비스이며 장애, CORS, 외부 스크립트 로딩 문제는 게임 자체의 문제와 구분합니다.
- 기존 GitHub Pages 링크는 대체 실행 경로이지만 선택한 Git 태그와 같은 버전이라는 보장은 없습니다.

## 게임별 실제 플레이 소개

- 전시 대상 8개 게임은 각 게임의 공개 `#/showcase` 소개 화면을 제공합니다. 소개는 GameKit `scenario` 기반의 장면 시간표와 **게임 본래 시뮬레이션·렌더러**로 구성하며, 영상 파일 재생이나 가짜 전투 렌더러로 대체하지 않습니다.
- 소개 화면에는 닫기, 다시 보기, 직접 플레이 전환을 제공하고 실행은 별도 격리 인스턴스에서 수행합니다. 프리뷰가 기존 저장·멀티플레이·진행 중인 게임을 변경하지 않도록 관리합니다.
- 게임 상세의 **소개 보기**는 최신 GitHub Pages의 `#/showcase`를 엽니다. 채널별 Stable/Nightly 태그 실행과 정확히 같은 버전을 보장하지 않으므로 별도 링크·안내를 유지합니다.
- 바운코의 28초 소개는 대표 구현 사례이며, 다른 게임의 소개 길이와 시연 명령·카메라는 각 게임이 소유합니다.

## 게임 정보 읽기 (전환 중)

- `GAMES` 항목에 `source:'manifest'`가 있는 게임은 설명과 릴리즈 정보를 `https://byh-playground.github.io/<저장소>/bloom-game.json`(게시본)에서 읽습니다. 규격은 [MANIFEST.md](MANIFEST.md)입니다. 지금은 **바운코만** 해당하고, 나머지는 `GAMES` 배열의 설명과 GitHub 태그 API를 씁니다.
- 매니페스트 게임은 GitHub API를 호출하지 않습니다. Nightly는 파일의 `nightly` 값을 표시하고 실행은 게임의 GitHub Pages(`main` 최신)이며, Stable은 `stable.version`의 `v` 태그를 GitHack에서 미리보기합니다. 소개 보기는 `showcase` 주소를 그대로 쓰고 없으면 버튼을 숨깁니다.
- 파일을 못 받거나 규격에 맞지 않으면 그 카드는 `조회 실패`와 "게임 정보를 불러오지 못했습니다"로 표시하며, 이전 값이나 `GAMES`의 값으로 채우지 않습니다. 성공한 게시본 원문은 `bloom-playground-releases-v4`에 5분간 캐싱하고 읽을 때 다시 검증합니다.

## 구현

- 브라우저에서 [GitHub REST matching refs API](https://docs.github.com/en/rest/git/refs#list-matching-references)의 `/git/matching-refs/tags/`를 저장소당 한 번 요청하고 반환 배열 전체에서 최신 채널 태그를 고릅니다. 이 API에 정의되지 않은 페이지 번호는 사용하지 않습니다. 응답 본문을 읽는 단계까지 9초 제한을 적용합니다.
- 각 저장소의 상태를 `조회 중`, `조회 실패`, `조회 완료`로 관리합니다. 미등록은 조회에 성공한 채널에 태그가 없을 때만 표시합니다. 목록·상세·빈 결과·집계에서 로딩이나 실패를 미등록으로 취급하지 않습니다.
- 성공한 결과만 저장소별 `checkedAt`과 함께 `sessionStorage`의 `bloom-playground-releases-v3`에 5분간 캐싱합니다. 실패는 저장하지 않으며, 새로고침하면 유효한 성공 캐시를 재사용하고 나머지 저장소만 요청합니다. 손상된 값, 미래 시각, 만료된 값, 채널 규칙에 맞지 않는 태그는 무시합니다. 저장소 접근이 차단돼도 조회는 계속합니다.
- 목록의 `다시 조회`는 실패한 저장소만, 상세의 같은 버튼은 해당 게임만 다시 조회합니다. 진행 중인 저장소의 중복 요청을 막으며 검색·필터·상세 경로는 유지합니다.
- 같은 상세 내용은 다시 그리지 않습니다. 채널 선택은 URL 변경으로 처리하고, 비동기 갱신 때 카드·상세의 키보드 포커스를 보존합니다. 상세를 닫으면 목록 갱신 이후에도 해당 게임의 열기 버튼으로 돌아갑니다.
- 고유 태그는 게임 저장소의 `.github/workflows/release-tags.yml`에서 발행하며, 실제 태그 계약의 원본은 `byh-playground/bloom-reference`의 재사용 워크플로입니다.
- 페이지는 CSS·그래픽·JavaScript가 한 HTML에 들어 있는 **정적 전시 사이트**입니다. 게임은 각자 독립 저장소의 `index.html` + 원본 자산을 사용합니다.
- 현재는 세계관 Pages의 하위 경로를 사용하는 초기 공개 주소입니다. 독립 도메인/저장소 이전 시에는 상대 경로 없이 포팅할 수 있습니다.

## 확인할 내용

- 로딩·네트워크 오류·태그 미등록 구분 및 실패한 저장소만 다시 조회
- 성공 캐시 재사용, 만료·손상·미래 시각·잘못된 태그·스토리지 차단 처리
- 100개가 넘는 응답에서도 배열 전체의 최신 태그 선택 및 본문 응답 시간 제한
- Stable/Nightly/전체 탭과 장르/검색 조합
- 명시한 채널의 미등록 상태, 필터와 독립적인 기본 상세 채널, 뒤로·앞으로 가기
- 320~1440px 반응형, 긴 태그 줄바꿈, 비동기 갱신·채널 전환·닫기 시 키보드 포커스
- 사용자 플레이 전에는 해당 태그 실행 환경을 별도로 검증 (특히 WebGL, CDN, RTC)
